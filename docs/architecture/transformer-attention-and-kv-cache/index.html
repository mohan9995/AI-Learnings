Transformer Attention & The KV Cache: Memory Footprint and Optimization

A deep dive into Multi-Head Attention, Grouped-Query Attention (GQA), FlashAttention-3, and PagedAttention memory management in LLM serving.

#Transformers#Attention#KV Cache#vLLM#Inference Optimization

When deploying Large Language Models (LLMs) in production, serving bottlenecks are rarely compute-bound during the generation phase; they are memory-bandwidth bound. The primary consumer of GPU VRAM during serving is not just model weights, but the Key-Value (KV) Cache.

In this architecture guide, we analyze the mathematics of the KV cache, calculate exact VRAM footprints, and examine how Grouped-Query Attention (GQA) and PagedAttention resolve memory bottlenecks.

1. Multi-Head Attention vs Grouped-Query Attention (GQA)

In traditional Multi-Head Attention (MHA), each attention head i∈{1,…,H}i \in \{1, \dots, H\}i∈{1,…,H} projects distinct Query, Key, and Value vectors:

3. PagedAttention: Virtual Memory for LLMs

Standard PyTorch allocations require contiguous memory blocks. Because request generation lengths are unpredictable, naive servers pre-allocate the maximum context length (e.g., 8k or 32k tokens), resulting in:

  • Internal fragmentation: Up to 60–80% of allocated memory remains unused if queries terminate early.
  • External fragmentation: Free memory slots scattered across VRAM cannot be merged.

The Page Table Mechanism

PagedAttention (Kwon et al., vLLM) solves this by dividing KV tensors into fixed-size physical blocks (e.g., 16 tokens per block). Non-contiguous physical memory blocks are mapped through a logical page table:

graph LR
    L1[Logical Block 0: Tokens 0-15] --> PT[Page Table]
    L2[Logical Block 1: Tokens 16-31] --> PT
    L3[Logical Block 2: Tokens 32-47] --> PT
    
    PT --> P_A[Physical Block 7: GPU Memory]
    PT --> P_B[Physical Block 2: GPU Memory]
    PT --> P_C[Physical Block 14: GPU Memory]

This dynamic allocation pattern reduces memory waste to under 4%, allowing production engines to boost batch sizes and throughput by 2x to 4x.

4. FlashAttention-3 and Kernel Fused Reductions

While PagedAttention optimizes memory capacity, FlashAttention-3 optimizes memory bandwidth speed. By tiling the softmax computation in SRAM without writing intermediate N×NN \times NN×N attention matrices to high-bandwidth memory (HBM), FlashAttention-3 achieves near theoretical hardware peak utilization on NVIDIA Hopper H100 and Blackwell architectures.

Frequently Asked Questions

Why does the KV Cache grow linearly with sequence length?

During autoregressive decoding, each newly generated token attends to the Key and Value vectors of all previous tokens. To avoid recomputing these projections at every step, Key and Value tensors are saved in GPU VRAM, occupying O(seq_len) memory per request.

How does Grouped-Query Attention (GQA) reduce KV cache size?

In standard Multi-Head Attention (MHA), every Query head has its own Key and Value head. GQA shares a single Key-Value head across a group of Query heads (e.g. 8 Query heads per 1 KV head), slashing KV cache memory by 8x while preserving downstream benchmark quality.

What problem does PagedAttention solve in vLLM?

PagedAttention eliminates external and internal memory fragmentation by partitioning the KV cache into non-contiguous virtual memory blocks (pages), mirroring operating system virtual memory page tables and boosting GPU serving throughput by 2–4x.
