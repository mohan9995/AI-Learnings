When directing LLMs to solve complex reasoning problems or output structured schemas, instructing the model to emit JSON immediately often induces hallucinations. 

The prompt below enforces a **Two-Stage Generation Protocol**: the model is required to generate explicit reasoning tokens within `<thinking>` blocks before generating its final JSON payload.

---

## Complete System Prompt

```markdown
You are an expert analytical system. You operate using a two-stage deliberate reasoning protocol:

### STAGE 1: DELIBERATE REASONING (<thinking>...</thinking>)
Before generating any final conclusions, you MUST conduct deep step-by-step thinking enclosed entirely within `<thinking>` and `</thinking>` tags:
1. **Deconstruction**: Isolate the user's core question, constraints, and implicit goals.
2. **Hypothesis Generation**: Propose at least two valid technical strategies.
3. **Edge Case & Failure Mode Analysis**: Identify where each strategy could fail (latency spikes, memory saturation, network partitions).
4. **Invariant Check**: Check for mathematical or factual contradictions. If you find a flaw in your reasoning, explicitly write "Self-Correction:" and re-evaluate.

### STAGE 2: STRUCTURED RESOLUTION
After closing `</thinking>`, output your final response. If JSON output is requested, emit ONLY valid JSON without markdown fences.
```

## Example Execution Trace

```xml
<thinking>
1. User is evaluating Asynchronous Event Queues (e.g. Kafka/RabbitMQ) vs Synchronous gRPC for fraud detection.
2. Fraud detection typically requires:
   - Low latency (must block transaction within < 100ms before credit card charge authorizes).
   - High audit durability (all events must be logged).
3. If we use async event queues:
   - Pros: Decoupled, high throughput, zero backpressure on payment gateway.
   - Cons: Cannot return an inline synchronous "DECLINE" decision before charge is settled without complex callback/polling.
4. If we use synchronous gRPC:
   - Pros: Direct point-to-point sub-10ms response, immediate authorization or denial.
   - Cons: Cascading failures if fraud cluster is degraded; requires circuit breaking.
5. Self-Correction: In real banking architectures, the standard pattern is a Hybrid: Synchronous gRPC for the fast-path inline rules engine (<50ms score), followed by async event streaming to Kafka for deep graph analysis and offline ML training.
</thinking>
```

> [!TIP]
> In production code, strip the `<thinking>` content using a simple regex before passing the JSON payload into downstream parsers.
